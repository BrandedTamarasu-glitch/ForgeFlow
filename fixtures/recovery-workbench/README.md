# Repository recovery experiment

This exploratory follow-up changes the task, not the historical pilot scores. Trials inspect a small multi-file draft service, make justified repairs in an isolated copy and run local tests. They do not receive hidden acceptance checks, defect locations, expected counts or the corrected implementation. A paired clean implementation detects unnecessary source changes. The material is newly authored synthetic code under the repository MIT license.

The frozen `protocol.json` defines 18 trials: defective/clean versions, three repetitions and three arms (baseline, short checklist, full procedure). Order rotates within each case so every arm occupies every position once. Every trial receives a fresh context, identical task and budget, and its own source copy. Only treatment text differs. The portable task wording is in `task-template.txt`; it is a normalized copy of the already-frozen local baseline prompt. Exact task prompts and final artifacts are retained locally. The full treatment snapshots the canonical persistence procedure; the checklist is a separate abbreviated treatment.

The task asks for the smallest justified corrections to the documented save/reopen/cleanup behavior, preserving APIs and format compatibility, leaving source unchanged if already correct. Trials may edit only `src/shelf.js` and `src/format.js`, plus add tests. They may use 12 tool calls and a 200-word final report, enforced by instruction. The backend, README and package metadata remain fixed. Network use and outside-workspace reads are prohibited by instruction, not OS isolation.

`acceptance.js` loads repaired source against the frozen backend and returns eight binary behavioral checks. It receives no arm label. `scripts/forgeflow/test-recovery-workbench.js` verifies frozen hashes and confirms the defective starting point fails concurrent saves and publication/cleanup while the corrected control passes all eight. Tests cover serial reopen, concurrent accepted writes, deduplication, cleanup publication, old-format migration, unknown-format no-write behavior, removal failure and orphan reclamation. The suite is bounded and does not prove arbitrary schedules, disk durability or all user-visible recovery behavior.

The prespecified exploratory trigger is at least two additional complete defective-case repairs out of three versus baseline, with all three clean controls passing without source edits and no formerly passing acceptance check regressing. Either checklist or full procedure can trigger broader testing. If triggered, retest all previously trialed capabilities, including the earlier change-propagation and visual-acceptance pair. A trigger supports further evaluation, not activation or statistical significance. A null result does not prove equivalence or feature uselessness.

Existing workflow and two-arm skill evaluation formats are unchanged; this three-arm experiment is separate. Keep actual results distinct from fixture-oracle verification. Preserve all attempts, failures, source edits and unknown resource metrics. Exact model identity, tokens and cost are unavailable. Do not infer a benefit merely because tasks are harder, or repeatedly change the cases until a preferred result appears.

## Control validity discovered during execution

The intended clean control passes the eight frozen checks but has a reader/reclamation race outside their coverage. A trial repaired it, and `node fixtures/recovery-workbench/diagnostic.js` independently reproduces `missing generation`: a reader selects g0, a second shelf publishes g1 and sweeps g0, then the first reader reads g0. This post-freeze diagnostic is deliberately separate from primary scoring. Source edits on this control cannot be equated with false findings. The frozen protocol and primary results remain unchanged; any replacement control needs a new version and fresh trials.

See [the completed 18-trial results](../../docs/recovery-workbench-results.md). No accuracy gain was measured; the post-freeze diagnostic invalidates interpretation of control edits as false positives.
