# Benchmark verification fixtures

Run `node scripts/forgeflow/test-benchmark-verification.js` from the checkout. This fixture is newly authored synthetic material under the repository MIT license. Its source identity is the containing Git revision plus any uncommitted diff; no external benchmark data or captured device results are reused.

`model.js` freezes a four-item sum-of-squares workload with independently calculated expected output 87. Two instrumented JavaScript paths perform the calculation. Counts increment inside the executed paths, independently of requested-backend labels. Disabling the synthetic vector backend actually selects the CPU loop; forbidding fallback fails before either path runs. Re-enabling restores the vector path. A seeded ignored-disable defect leaves dispatch unchanged and fails qualification. Neither path uses real vector hardware, GPU or NPU APIs.

The frozen protocol has one warmup and three measured repetitions per arm with alternating order. It retains every row, including incorrect or failed results. A deterministic clock model assigns 8 ms to the CPU path and 2 ms to the vector path; these numbers are authored examples, never wall-clock measurements. The assessor checks the exact schedule, units/protocol, every output, executed-path evidence and controls before reporting per-batch latency and per-item throughput. Memory, power and energy remain null because the fixture has no corresponding instrumentation.

Tests reject fallback mislabeled as acceleration, ignored controls, wrong results, NPU attribution, missing/duplicate/reordered samples, failed warmups, timeouts, mixed/missing execution evidence, invalid timing, inflated completion counts, changed protocols and broken controls. Passing the clean synthetic case is fixture qualification only. It establishes neither performance benefit nor reviewer accuracy. F4.2 separately records actual CPU measurements and a real-project review comparison. Production use needs the project's actual workload/oracle, runtime completion evidence, raw measurements and independently challenged controls.

The [actual CPU example](CPU.md) now records bounded real timings and execution controls. Its observation and the revised real-project evaluation plan are in [the CPU pilot report](../../docs/benchmark-cpu-pilot.md); the completed model comparison favored baseline on its selected cases.
