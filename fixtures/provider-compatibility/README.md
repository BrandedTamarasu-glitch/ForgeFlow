# Provider compatibility fixtures

Run `node scripts/forgeflow/test-provider-compatibility.js`. The fictional readings protocol uses two explicit versions; its payload cases and contract are in `corpus.json`. All data is newly authored synthetic material under the repository MIT license, with no captured account records or credentials.

The checkout-only model validates required numeric fields and timestamp units, rejects unsupported/incomplete responses, and ignores permitted additive fields. Its per-provider state retains the last valid observation with an explicit stale status after failed refresh. Controlled promises and a manual clock exercise independent failures, cache expiry, timeout, explicit cancellation, late completion, request supersession and recovery. Only normalized numeric values/timestamps and bounded error codes leave the model. A fake sentinel verifies raw error/payload material is not emitted; it is not a credential.

The adapter and timer are synthetic. Abort-signal observations do not prove an external CLI/process/socket terminates; late-result suppression is tested separately. There is no network, live provider/version qualification, retry/backoff, pagination, actual timer scheduling, authentication or UI/accessibility observation. This is executable procedure evidence, not another runtime provider manager or proof of model benefit. Application adapters need their own fixtures and actual runtime checks before qualification. Later pilots must independently validate clean controls and use hidden executable checks rather than infer benefit from these examples.
